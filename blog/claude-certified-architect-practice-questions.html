Claude Certified Architect: Practice Questions With Explanations

Ten scenario questions written for this page to rehearse the kind of judgment an architect certification tests: picking the right Claude feature for a situation and knowing why. Every answer links to the official docs.

November 17, 2026 10 min read Career
Quick answer

Claude Certified Architect: Foundations is Anthropic's proctored certification for solution architects who design and build agent systems with Claude. It is open to members of the Claude Partner Network, and the official preparation courses are in the Anthropic Partner Academy. The ten questions below are not taken from the exam. They are original practice scenarios on topics an architect works with daily (tool use, prompt caching, batch processing, Claude Code configuration, context management and grounding), with explanations based on Anthropic's public documentation.

What is the certification, in short?

Anthropic introduced Claude Certified Architect, Foundations on March 12, 2026, together with the Claude Partner Network, as its first technical certification. A July 2026 article describes four role-based credentials (Associate, Developer and Architect at Foundations level, and Architect at Professional level). Exams are proctored through Pearson, require identity verification, and award a Credly badge. Partner Network membership is free for firms. For the program background, see our Claude Certified Architect overview.

Anthropic's public pages do not publish question counts, timing or domain weights, so treat third-party numbers with care and check the Partner Academy for the current exam guide.

How to use these questions

Answer each one before reading the explanation. If you miss one, read the linked doc section rather than memorizing the letter; real scenarios will be worded differently.

Question 1: the tool use loop

Your application sends a request with a get_inventory tool. The response comes back with stop_reason set to "tool_use". What should your code do next?

  1. Send the same request again with tool_choice set to none
  2. Run the tool, then send a new request that includes Claude's response and a user message with a tool_result block carrying the matching tool_use_id
  3. Show the tool_use block to the end user as the answer
  4. Wait; Anthropic runs client tools automatically

Answer: B. Client tools run in your application. Claude returns a tool_use block; you execute it and return a tool_result with the same id so Claude can finish the answer. Only server tools such as web search run on Anthropic's side. Source: Tool use with Claude.

Question 2: guaranteed schema

A downstream service crashes when a tool call is missing a required field. You want tool inputs to always match your JSON schema. What is the most direct fix?

  1. Add "always follow the schema" to the system prompt
  2. Lower the temperature
  3. Add strict: true to the tool definition
  4. Retry until the output parses

Answer: C. Strict tool use makes Claude's tool calls match the schema exactly. Prompting helps but does not guarantee it, and retry loops waste tokens. Keep validation in your service anyway. Source: Tool use with Claude.

Question 3: what breaks the cache

A support agent caches a long system prompt and tool list. Cache hit rates collapse after a release in which the team appended today's date to one tool's description. Why?

  1. Dates cannot be cached
  2. The cache prefix runs tools, then system, then messages, and changing a tool definition invalidates every level after it
  3. The cache only covers messages
  4. Caching needs a 1-hour TTL to work at all

Answer: B. Changing tool names, descriptions or parameters invalidates the tools, system and messages caches. Keep stable content first and move changing values to the end of the prompt. The default cache lifetime is 5 minutes, with a 1-hour option at a higher write price. Source: Prompt caching.

Question 4: a large job with no deadline

You need to classify a few hundred thousand archived documents. Nobody needs results before tomorrow, and cost matters most. Which approach fits?

  1. Thousands of parallel synchronous requests
  2. The Message Batches API
  3. One request with every document in it
  4. Streaming responses

Answer: B. Batches cost 50 percent less, most finish within an hour, and anything not done in 24 hours expires. One batch holds up to 100,000 requests or 256 MB, so split the job across several batches. Source: Batch processing.

Question 5: a rule that must hold

Security requires that Claude Code never reads .env files in a repository. A teammate proposes adding "never read .env files" to CLAUDE.md. What should you use instead?

  1. Nothing; CLAUDE.md is enforced
  2. A Read deny rule in the project's .claude/settings.json
  3. A skill that reminds Claude about secrets
  4. Plan mode for every session

Answer: B. CLAUDE.md shapes what Claude tries to do; permission rules are enforced by Claude Code itself. Deny rules are checked first and an allow rule cannot override them. For hard OS-level limits, add the sandbox. Source: Configure permissions.

Question 6: deterministic automation

Every time Claude edits a TypeScript file, the formatter must run. Instructions in CLAUDE.md work most of the time but not always. What makes it happen every time?

  1. A PostToolUse hook matching the edit tools
  2. Repeating the instruction in every prompt
  3. A subagent that formats files
  4. Raising the effort level

Answer: A. Hooks are commands Claude Code runs at fixed lifecycle points, so they do not depend on the model remembering. Source: Hooks reference.

Question 7: keeping the main context clean

An agent must investigate a large codebase before proposing a change. The file reads fill the main conversation and later answers get worse. Which design helps most?

  1. Ask the user to paste only relevant files
  2. Delegate the investigation to a subagent, which reads in its own context window and returns a summary
  3. Turn off auto-compaction
  4. Put the whole codebase in CLAUDE.md

Answer: B. Subagents run in a separate context window; only the summary returns. Note that their requests still count toward usage limits. Source: Create custom subagents.

Question 8: surviving compaction

During a long refactor, Claude forgets a constraint you gave in the second message once the session compacts. Where should the constraint have gone?

  1. In a longer, more emphatic chat message
  2. In the project-root CLAUDE.md or the plan file, which are re-injected from disk after compaction
  3. In a path-scoped rule, which is always kept
  4. Nowhere; compaction keeps every message

Answer: B. The root CLAUDE.md, unscoped rules, auto memory and the plan are re-injected after compaction. Path-scoped rules are summarized away and reload only when a matching file is touched. Source: Explore the context window.

Question 9: shared know-how, loaded on demand

Your team has a 300-line database migration procedure. Putting it in CLAUDE.md costs tokens in every session, even unrelated ones. What is the better home?

  1. A project skill in .claude/skills/, committed to the repository
  2. A personal note in each developer's home folder
  3. A longer system prompt
  4. An MCP server

Answer: A. Only a skill's description loads at startup; the body loads when the skill is used. Committing it shares it with the team. Sources: Skills and Manage costs.

Question 10: grounding a long-document answer

A compliance assistant answers questions about a 200-page policy and sometimes cites clauses that do not exist. Which change addresses this most directly?

  1. Ask Claude to extract word-for-word quotes first, answer only from them, and say it does not know when no quote supports an answer
  2. Shorten the system prompt
  3. Switch to streaming
  4. Remove the document and rely on general knowledge

Answer: A. Anthropic's guidance for long documents is to extract quotes first, allow "I don't know", and drop claims without a supporting quote. It also notes these techniques reduce errors without eliminating them. Source: Reduce hallucinations.

What pattern runs through these answers?

  • Enforce in the system, not in the prompt, when something must always happen: permissions, hooks, strict schemas.
  • Keep context lean and durable: subagents for volume, skills for on-demand know-how, files for anything that must survive compaction.
  • Match the API feature to the workload: caching for repeated prefixes, batches for large jobs without a deadline.
  • Ground and verify anything a business will act on.

FAQ

Are these real exam questions?

No. They were written for this page to practice the same kind of reasoning. The exam content is confidential to Anthropic and the official preparation courses are in the Anthropic Partner Academy.

Who can take the Claude Certified Architect exam?

Members of the Claude Partner Network. Firms join for free and register their practitioners through claude.com/partners.

How is the exam delivered?

Anthropic says every exam is proctored through Pearson, test takers verify their identity first, and passing earns a digital badge through Credly.

What comes after Foundations?

Anthropic's role-based path starts at Foundations level and moves to Professional level. Claude Certified Architect: Professional is the next step for architects.
