22 Rules to Stop Hitting Claude Token Limits

Most limit problems aren't about asking too much. They come from re-reading, model switching and oversized inputs. Twelve must-do rules and ten small habits that fix that.

October 23, 2026 10 min read Cost Optimization
TL;DR

Most people don't run out of Claude limits because they ask too much. They run out because every message makes Claude re-read the whole conversation, and a handful of habits quietly multiply that cost: the wrong effort level, switching models mid-chat, returning to stale chats, and attaching screenshots and PDFs raw. Below are 22 rules, split into 12 non-negotiables and 10 habits, that cut usage without making your prompts worse.

Why Your Limits Disappear Faster Than You Expect

Two mechanics explain almost every rule in this guide.

1. Every message re-reads the conversation. Claude doesn't "remember" a chat the way you do. Each new message sends the full history back through the model. Prompt caching makes that cheaper, but the cache expires when you pause and is tied to the specific model. A long chat you return to after lunch is paid for at full price again.

2. Limits are shared and windowed. Usage counts against a rolling 5-hour window and a weekly cap. Tokens spent on clarifying back-and-forth, web searches you didn't need, or an oversized image come out of the same budget as the work you actually care about.

Once you see those two, the rules stop looking like a random list of tips. They are all variations on: send less, re-read less, and don't break the cache.

A note on numbers: Figures such as token counts per screenshot or dollar-value comparisons between models come from community measurements and will vary with your plan, model versions and content. Treat them as orders of magnitude, and check your own numbers with /usage (Claude Code) or the Usage page in Settings (Claude app).

Part I: The Non-Negotiables (Rules 1–12)

The principle for this part: don't overcomplicate it. These twelve changes cost nothing and save the most.

Rule 1: Use Medium effort. Never Max.

Higher effort means more thinking tokens on every reply, and for most tasks it doesn't change the result. Default to Medium. Drop to Low for grammar fixes, renames and other trivial edits. Reserve High for rare, genuinely hard problems, and treat the top tier (Max/Extra) as something you reach for almost never.

/effort medium

Rule 2: Save the free limit reset for a bad day

If your plan or promotions offer a one-off reset or bonus, don't burn it on Monday morning. Your normal limits renew on a schedule anyway, so the reset is most valuable on the day you're stuck mid-project and out of budget.

Rule 3: Use the workhorse model in every chat. Don't default to the premium one

The most expensive model burns through your allowance several times faster than the one below it. By the community's rough comparison, the same monthly budget that covers thousands of dollars of work on Opus 5.5 covers a fraction of that on the top-tier model. If you need a faster answer, lower the effort, not the model. Move up only when the cheaper model has demonstrably failed at the task.

Rule 4: Never switch models between messages

Each model keeps its own cache. Switch from one model to another mid-chat and the new model has to read the entire conversation from scratch at full price. If you want a different model, start a new chat (or finish the task first and switch at the boundary).

Rule 5: Don't return to an old chat

The cache is reset when you pause, so resuming a day-old thread means re-reading all of it. Instead, ask Claude to compress the chat into about ten lines, open a new one, paste the summary and continue.

Summarize this conversation in 10 lines: decisions made, current state, open questions, next step.

Rule 6: For quick questions, write "No web search"

Web search pulls pages of results into the context. For a simple factual or conceptual question it's pure overhead. Keep research mode for questions that truly need 20+ sources, not for ones where the answer is one sentence.

Rule 7: Plan in text. Ask for the file at the end

Don't open with "Build a 12-slide deck." Agree on the outline and each section in plain text first, which is cheap to iterate on. Only then say: "Now assemble exactly this deck." Regenerating a finished file over and over is the expensive part.

Rule 8: Highlight. Never ask for a full rewrite

If you only want one part changed, say so explicitly: "Rewrite only this section. Leave everything else untouched." Claude then rewrites a few paragraphs instead of the entire document. In Claude Code the equivalent is pointing at a file and line range rather than saying "refactor the module".

Rule 9: Connect apps and tools on demand

Every connected app, connector or MCP server adds tool definitions to the context, and that cost is paid on every message whether or not you use the tool. Switch off everything you don't need for the current task.

Rule 10: Trim prompt boilerplate

Anthropic's own prompting guidance has changed with newer models: they follow plain, direct instructions well and need less hand-holding. Strip legacy incantations like "think step by step" and "take a deep breath" from your saved prompts. They add tokens and, with reasoning models, often add nothing. Ask for the outcome and the constraints, then stop.

Rule 11: Crop every screenshot. Convert every PDF

A full-screen screenshot can cost thousands of tokens, while a tight crop of the relevant region costs a small fraction of that. PDFs are worse: layout, fonts and embedded images all get processed. Convert the PDF to Markdown or plain text first (for example, paste it into a Google Doc and download as Markdown) and attach that instead.

Rule 12: Stop scheduled tasks you don't read

A task that runs every hour is 24 runs a day, every day. If nobody reads the output, it's a silent drain on your limit. Audit your scheduled tasks and loops, and delete or slow down any whose results you never open.

Part II: The Basics (Rules 13–22)

The principle for this part: small habits, big savings. None of these is dramatic on its own, and together they're the difference between hitting the wall on Wednesday and making it to Sunday.

Rule 13: Start every task with "ask me questions"

You don't need a 500-word prompt. Write two sentences about the goal and add: "Ask me any questions you need before you start." Claude fills in the gaps by asking, you answer in a few words, and you skip the long prompt that tried to anticipate everything.

Rule 14: Put all your requests in one message

Three separate messages mean three full re-reads of the conversation. One message with all three requests means one. Batch related asks, numbered if they're distinct.

Rule 15: Speak, don't type

Typing makes people terse and lazy ("make it better"). Dictating is faster and naturally gives Claude more context in fewer attempts, which means fewer follow-up messages.

Rule 16: Don't correct Claude. Start over

Every "No, I meant..." stays in the chat permanently and is re-read on every later message. When the answer misses, don't patch it. Edit your original prompt (or restart) so the wrong turn is removed from the history instead of piling up.

Rule 17: One chat = one topic

A new subject deserves a new chat. Mixing topics bloats the context with material that's irrelevant to the current question, and you pay to re-read it every time.

Rule 18: Keep instructions under 2,000 words

Custom instructions, system prompts and style guides are re-read on every turn. A 6,000-word rulebook is a tax on every message. Keep the permanent part short and put task-specific detail in the message where it belongs.

Rule 19: Add every reused file to a Project

Upload the same file into five chats and Claude processes it five times. Put it in a Project once, and it's cached and shared across the chats in that project.

Rule 20: In Claude Code, one task, then /clear

Finish a task, then run /clear before starting the next. Leftover context from task A makes task B slower and more expensive for no benefit. Keep your CLAUDE.md under roughly 200 lines, since it loads at the start of every session.

/clear      # new task, clean context
/compact    # same task, but the history got long
/usage      # see where the budget is going

Rule 21: Split your day into three sessions

The 5-hour window plus the weekly cap rewards pacing. Plan three working blocks: morning, afternoon, evening. Before each, check your usage so you know whether to run heavy work now or defer it to a block when the window has reset.

Rule 22: Ask Claude to make images, but rarely

Claude can generate graphics through code, such as SVGs, charts and diagrams, but iterating on visuals consumes a lot of tokens. Generate them deliberately, with a clear brief, not as a casual "try another version" loop.

The 5-Minute Setup: Do These Six Things First

If you only do a few things after reading this, do these. Together they cover the majority of avoidable spend.

  1. Set effort to Medium and your default model to the workhorse tier (Rules 1, 3).
  2. Stop switching models mid-chat (Rule 4).
  3. Disable connectors and MCP servers you aren't using today (Rule 9).
  4. Delete or slow down scheduled tasks nobody reads (Rule 12).
  5. Move reused files into a Project and shorten your instructions below 2,000 words (Rules 18, 19).
  6. Use /clear between tasks in Claude Code and trim CLAUDE.md (Rule 20).
